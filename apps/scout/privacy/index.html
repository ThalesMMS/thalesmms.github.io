Scout privacy policy

Effective September 5, 2026

How Scout handles data, including the services and integrations you choose to use.

Documents and local indexes

Saved reports remain in the selected file workspace. Corpus chunks and embeddings are persisted in a local SQLite index, while structured-report definitions and settings are stored separately. Indexing can create another local copy of source text.

Deleting an original corpus file or a saved report does not automatically prove that its indexed content, exports or backups have been removed. Manage each stored copy separately.

Optional language-model traffic

The default language-model and embedding endpoints are empty. Once configured, AI completion, chat, structured-report assistance and dictation refinement can transmit document passages, instructions, conversation context and retrieved corpus excerpts to the selected provider.

Enabled automatic completion can make a request after a typing pause. Refinement is enabled by default in settings, but requires a usable language-model provider. Review these controls before entering sensitive text.

Embeddings and retrieval

A configured embeddings service receives text chunks during indexing and query text during semantic search. It may run locally or on another computer. Calling a service local does not establish how that service stores requests or whether it contacts other providers.

Microphone and downloads

Local Whisper processes microphone audio through the configured local executable. Its installer contacts GitHub and Hugging Face to obtain software and model files.

Remote dictation streams microphone audio to the configured WebSocket service and includes the configured API key in its session request. Use a trusted encrypted endpoint. Optional refinement sends transcript text to the language-model provider separately.

Credentials and account access

API keys are currently saved as plaintext in the local settings file. Protect that file and any backups and do not include it in support attachments.

The optional Codex flow opens an OpenAI sign-in page and stores or uses an authentication JSON file. It contacts OpenAI for authentication and model requests. Signing out removes Codex authentication fields from the selected file and can affect another application sharing that file.

Diagnostics and deletion boundaries

The audited application code does not configure a third-party advertising, analytics or crash-reporting service. Local errors and status information can still be present in application output.

Removing local files, indexes or credentials cannot delete information already sent to an AI or speech provider. Provider retention and deletion depend on the selected service, and exported files or system backups must be managed separately.

This support website

This static website does not use analytics scripts, forms, or third-party tracking scripts. GitHub Pages handles requests to the website under its own hosting and privacy practices. Visiting a source repository or contacting another service is subject to that service's policies.
