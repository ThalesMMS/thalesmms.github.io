DICOM tools for AI agents support

Setup, troubleshooting, and a direct contact for help.

Choose the component

Use dicom-skill for standalone shell workflows, the integrated plugin for its combined tools, or dicom-viewer-mcp-app for the standalone prototype. Current integrated builds use Node.js and uv; Docker is required only for workflows using a temporary Orthanc receiver.

In current chat-host builds, the composite viewer provides a user-driven Query/Retrieve interface. Coding-host builds can expose query/download tools to the agent and write a self-contained HTML preview. Follow the setup for your exact component and host.

Configure a PACS

Supply authorized endpoint, AE title and port information. In the integrated plugin, DICOM_MCP_CONFIG selects the shared node configuration. Verify connectivity before retrieving or sending data.

Open images

The separate viewer reads a local dicom folder and supports uncompressed images. The integrated plugin additionally supports preparation workflows and local HTML output for hosts without inline MCP Apps.

Troubleshoot transfers

Check endpoint reachability, AE permissions, transfer syntax and destination receiver configuration. Temporary Orthanc workflows require Docker and create local storage.

Review outputs

Check anonymized files and rendered previews before sending or sharing. These tools do not establish diagnostic suitability or certify de-identification.

Integrated suite and standalone tools

The integrated plugin combines a query/download MCP server, shell tools for sends and local processing, and a composite viewer. Chat and coding hosts expose different tools and rendering routes. Older plugin builds and the standalone dicom-skill and viewer repositories do not have identical capabilities.
