AutoComp for Safari privacy policy

Effective November 2, 2026

How AutoComp for Safari handles data, including the services and integrations you choose to use.

Scope and document access

This policy describes the Safari extension, including current builds with local models, review, assistant, dictation and search. Earlier Safari builds may offer only remote autocomplete. It does not describe the native macOS, mobile, Flutter, Chrome or OnlyOffice implementations.

The extension reads relevant Google Docs text, selections and cursor context for the action you request. Assistant and review operations can process more text than a short autocomplete request. Abbreviations can operate in other supported web text fields.

Local processing and model downloads

TXT phrase indexing and lookup run locally. Optional browser language models run inside the extension when supported. Installing model assets contacts the selected model host and creates a local model cache; local inference does not make installation offline.

A local phrase hit does not call the generation provider. Later AI requests may include previously inserted text as document context. A phrase index is not an anonymization tool.

Remote generation, search and audio

Remote autocomplete, assistant and review requests send the relevant document text, instructions and selected model to the configured generation endpoint. Connection tests also contact the selected service.

Optional semantic embeddings send selected report passages and search text to their separately authorized endpoint. A remote dictation service receives microphone audio through the configured streaming or batch route. Optional AI punctuation uses the selected assistant model and transcript context separately.

Credentials accompany authenticated requests. Use HTTPS for remote services; supported loopback integrations have separate connection rules. The destination controls logging, retention, training use and deletion.

Settings, indexes and credentials

Safari credentials and task settings are stored in extension-origin IndexedDB, not Apple Keychain. This store adds no encryption of its own and does not sync settings through iCloud. Content scripts do not receive the saved credential store.

Phrase and semantic indexes, model caches, abbreviations and other local extension data have separate lifecycles. Semantic indexes retain source passages; phrase normalization does not guarantee removal of names or identifying text. Protect exported configuration backups because they can contain API keys.

Folder access and external copies

Optional persistent folder access uses the containing app and remembered folder authorization. Source TXT files and library backups remain outside extension storage. Clearing an index does not delete those external copies.

Document changes applied to Google Docs become part of the document managed by Google and its sharing settings. Copied text, exported files and data already sent to a provider remain subject to their destination.

Your controls and diagnostics

Disable unwanted tasks, remove endpoint permissions, stop dictation and revoke microphone access to stop the corresponding activity. Remove local indexes and models through their controls and manage Safari extension data separately. Revoke API keys at their provider when needed.

The inspected extension does not configure a developer-operated document-upload or analytics service. Review diagnostic output and any backups before sharing them with support. Removing local data does not delete requests retained by a remote service.

This support website

This static website does not use analytics scripts, forms, or third-party tracking scripts. GitHub Pages handles requests to the website under its own hosting and privacy practices. Visiting a source repository or contacting another service is subject to that service's policies.
