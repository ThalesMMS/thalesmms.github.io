AutoComp for Safari support

Setup, troubleshooting, and a direct contact for help.

Enable the Safari extension

Open the containing macOS app, enable AutoComp in Safari Extensions, allow access to Google Docs and reload an editable document. The Google Docs integration depends on editor internals and may change.

Choose local or remote processing

Use extension options to select the provider for each task. Local browser inference requires the packaged runtime, a compatible browser/device and an installed model. Downloading a model does not activate it automatically.

For remote generation, enter the API base address, model and credentials, grant the requested host permission and test the connection. Review, assistant, embeddings and dictation can use different settings; a successful model-list test does not validate every operation.

Build a phrase or search library

Select TXT files or a library folder in options. The phrase index and semantic search index are separate. Semantic embeddings require their own endpoint and consent; lexical search can operate without embeddings.

Persistent Safari folder access requires a compatible signed containing app and shared App Group. Builds without that integration can use manual folder selection. Folder backups remain separate from the extension index.

Review proposals and dictation

Review proposed edits before applying them. Start microphone capture explicitly in the recorder tab and keep it open while dictating. The configured speech service can receive audio; optional AI punctuation can separately send transcript context to the selected language model.

Identify the edition when requesting help

Include Safari and macOS versions, the AutoComp build, selected provider and a sanitized error. The native macOS app, mobile editors, Flutter workbench, Chrome and OnlyOffice builds have different setup steps. Do not send documents, library backups or API keys.

Other AutoComp implementations

Native macOS uses Accessibility to work in supported text fields. Native iPhone/iPad and Android apps use their own editors. A separate Flutter workbench targets Windows, macOS, iOS and Android; its web target is unsupported.

Chrome and OnlyOffice implementations also exist. Their host integration and feature availability differ from Safari. These are separate implementations, not a promise of store availability, feature parity or shared privacy settings.
